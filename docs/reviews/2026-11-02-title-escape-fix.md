## 2. 原因

新写的「特殊文本往返」用例直接暴露出缺陷：

```
Expected: 含井号 # 与引号 " 的标题
Actual  : 含井号 # 与引号 \" 的标题
```

`_quote()` 会把 `"` 写成 `\"`（YAML 正确），但解析端只去掉首尾引号、没有还原转义，
于是「导出 → 导入」一次，标题里就多出反斜杠。用户看到的是**标题被静默改写**，
而且每往返一次可能继续劣化。

同时补上搜索的边界：此前只测了 `%`/`_`，没有验证 SQL 注入串、反斜杠、emoji、超长关键词。

## 3. 风险

- 【低】解析改为逐字符还原 `\"` 与 `\\`；对不含反斜杠的普通标题行为不变（已有 20+ 用例覆盖）。
- 【低】`_quote` 对「首尾有空格」也会加引号，导出更符合 YAML 语义；导出侧本来就会 `trim()` 标题。
- 【低】外部工具（Typora/VS Code）读到 `title: "含 \" 的标题"` 是合法 YAML，兼容性无影响。
