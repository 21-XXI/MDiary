## 2. 原因

两个问题都是写边界用例时暴露的：

1. **目录外读取**：导入器把 `![](../outside.png)` 直接 `p.join` 出路径并复制进附件库。
   「导入一个文件夹」不该读走该文件夹之外的文件（路径穿越）。现在只接受落在导入根目录内的引用，
   目录外引用保持原样、不复制。
2. **重复判定失效**：导出时正文会 `trimRight` 并补一个换行；导入端却把末尾换行算进正文，
   于是「导出 → 再导入同一库」判定为不同内容，产生副本。现在导入端同样 `trimRight`，
   与导出对称。

## 3. 风险

- 【低】目录外引用不再被复制：正文里保留原链接，预览会显示「附件缺失」占位（可见、不静默）。
  这比悄悄复制外部文件更安全。
- 【低】`trimRight` 会去掉正文末尾空行：Markdown 语义上无影响，且与导出行为一致。
- 【低】`_isInsideImportRoot` 用 `p.isWithin`，Windows 下大小写不敏感，符合预期。
