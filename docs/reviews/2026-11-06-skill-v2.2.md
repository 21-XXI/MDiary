## 2. 设计决定

- **必须云端**：按需求接云端大模型；本地 Ollama 不参与蒸馏（避免把"蒸馏"做成本地摘要）；
- **产物按时间分目录**，同一秒冲突加 `-2`，永不覆盖；
- **开关默认关**，关闭时不发请求；开关状态全局存 `settings.json`；
- **缺 soul.md 时先自动生成**，避免用户卡在"没有输入"；
- 16 KB 上限：skill 是给模型读的上下文，太大反而挤占窗口。

## 3. 风险与遗留

| 级别 | 项 | 说明 |
|---|---|---|
| 中 | 云端必需 | 没网/没 Key 就不能蒸馏；按钮置灰并提示，不影响日记与其他功能 |
| 中 | 全量蒸馏 | 每次读全部摘要，不做增量 diff；大库慢且费 token |
| 低 | 目录不清理 | `db/skill/` 只增不减（"不覆盖"的代价），需要手动删旧版本 |
| 低 | 质量依赖摘要 | 没有 `entry_summary` 的旧日记只能靠正文首行，蒸馏质量下降 |
| 低 | 隐私 | 蒸馏会把摘要发到云端；沿用 2.0.3 的云端开关确认与 DPAPI Key |
