# SKILL: mdiary-diary-segmenter

> 把用户上传的资料（笔记、聊天记录、旅行流水账、文章草稿）切分成**按日期的日记**，
> 输出 MDiary 可直接导入的目录结构：`父文件夹/日期/当期.md` + 同目录附件。

## 何时使用

- 用户给一堆散乱资料，想变成"某天发生了什么"的日记；
- 用户要把旧笔记 / 公众号草稿 / 语音转写整理进 MDiary；
- 用户需要**可导入**的结构，而不是一篇大长文。

## 输入

- 一段或多段文本（txt / md / 聊天导出 / 转写稿均可）；
- 可选：附件（图片、PDF、表格），文件名通常带日期或内容线索；
- 可选：用户要求的时间范围、第一人称/第三人称、语气。

## 切割规则（按顺序）

1. **先找显式日期**：`2026-11-06`、`2026/11/6`、`11月6日`、`昨天/前天/上周三`（结合资料里的"今天"锚点换算）。
2. **再找事件线索**：地点变化、旅程段落、话题切换；没有日期的按**相邻日期 +1 天**顺推，
   并在正文里避免写死"今天"以外的绝对日期。
3. **一天一条**：同一天的多段材料合并成一条；不要按段落拆成多篇。
4. **无法确定日期**时：用资料里最早的线索日，并在 `tags` 里加 `日期待确认`，
   不要编造具体日期。

## 输出格式（必须严格遵守）

```
<输出根目录>/
  2026-11-06/
    当期.md
    西湖.png
    发票.pdf
  2026-11-07/
    当期.md
```

`当期.md` 必须带 front matter：

```markdown
---
title: 杭州出差第一天
date: 2026-11-06
tags: [旅行, 工作]
---

正文（第一人称，2–5 段）。
```

正文里引用附件用**相对路径的文件名**（不要写绝对路径）：

```markdown
![西湖](西湖.png)

发票在 [发票.pdf](发票.pdf)。
```

> 导入时 MDiary 会把正文引用到的文件复制进库；**同目录下没被引用的文件也会作为附件导入**
> （因为文件夹名是日期）。所以附件放对文件夹即可。

## 写作要求

- **第一人称日记体**，像本人当天写的，而不是"总结报告"；
- 只写材料里有的事实；不确定的用"大概/记得/可能"，**不要补细节**；
- 每条 300–1500 字；同一天材料太少可以短，但不要注水；
- 保留具体名词：人名、地点、金额、时间、菜名——这是日记的价值；
- 不写"以下是整理"、"根据资料"之类元话语；
- 中文标点；不用 emoji（除非用户明确要）。

## 质量检查（交付前逐条过）

- [ ] 每个日期文件夹名是 `YYYY-MM-DD`；
- [ ] 每个文件夹里有且只有一个 `当期.md`；
- [ ] 每篇都有 `title` / `date` / `tags` front matter，`date` 与文件夹名一致；
- [ ] 正文里的附件引用都是**同目录文件名**，没有绝对路径、没有 `assets/` 前缀；
- [ ] 没有编造日期、金额、人名；
- [ ] 同一天的多段材料已合并，而不是拆成多篇。

## 附件处理

- 图片、PDF、表格：按**所属日期**放进对应文件夹，文件名保留原样（可去掉空格）；
- 文件名里带日期的（如 `2026-11-06-发票.pdf`）优先按文件名归日；
- 同一个附件只放一次；跨天共用的附件放在最早那天，并在正文里说明。

## 如果需要脚本辅助

`scripts/build_diary.py` 可以把结构化的 JSON 直接落成目录树：

```bash
python scripts/build_diary.py --manifest diary.json --out ./MDiary导入
```

JSON 格式见 `references/manifest.md`。适合"已经切好、只差落盘"的场景；
切分与写作仍由模型完成。
